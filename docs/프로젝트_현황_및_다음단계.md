> 범위: DevOps / BE 담당

**이 문서의 역할**
`ToDo_리스트.md`가 작업의 **상태와 우선순위**를 보여주는 현황판이라면, 이 문서는 같은 작업 ID별로
**왜 했는지(배경) · 어떻게 했는지(방법) · 무엇이 나왔는지(결과) · 근거가 어디 있는지**를 기록한다.
작업을 다시 손댈 때는 이 문서의 해당 ID 섹션을 먼저 읽는다.

**갱신 규칙**
- 작업을 시작하면 해당 ID 섹션에 "현재 상태/접근 방안"을 적고, 끝나면 "방법·결과·근거"를 채운다.
- 완료되면 섹션을 3장(완료 기록)으로 옮기고 `DN-xx` 번호를 붙인다. 원래 ID는 제목에 함께 남긴다.
- 상세 명령어·로그 원문은 저장소의 `테스트_도커_환경_구축_기록.md`에 있고, 여기에는 요약만 둔다.

  `posture_app` 생성·계정, 서버 변수(`max_connect_errors=10000`, `innodb_flush_log_at_trx_commit=2`, 권장 `innodb_buffer_pool_size≥256M`·`sync_binlog=0`),
  데이터 이전 불필요, 검증 절차(readiness, T-10 재생, `host_cache`, 시간대 확인).
- **다음**: DB 담당 적용 완료 → BE가 가이드 6.2·6.3 검증 → 통과하면 Done.

### DN-26 · D-11 `max_connect_errors` 상향 + HikariCP·헬스체크 점검 — 2026-10-04

- **배경**: DN-14에서 `Host '192.168.0.173' is blocked` 발생 → `flush-hosts`로 해제만 했음. 재발 방지가 목적.
